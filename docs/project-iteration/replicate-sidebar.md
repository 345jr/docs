# 复刻侧边栏

起点是一个很朴素的需求："在线编辑的侧边栏，和文档那边的侧边栏，是同一个项目，我希望它们看起来一样。"

结果这个"看起来一样"做了四轮。这篇文章记录每一轮改了什么、为什么会漏掉，最后回答一个更值得聊的问题：**这个任务的难点到底在哪**。

## 第一轮：选择复用，而不是复刻

编辑器侧边栏最初是一套自绘样式：`<details>` 做分类、手写的 hover 和激活态。它和文档站侧边栏的差异是全方位的——宽度、字重、圆角、hover 的灰度、激活态的样子，都不一样。

我的第一反应是自己调 CSS 把它"调像"。但很快意识到这是下策：文档站的侧边栏样式来自 Infima（Docusaurus 全局加载的基础样式库），主题色、hover 色、激活色全是 CSS 变量驱动的。手写一份"长得像"的样式，等于复制了一份会随时间漂移的副本——将来改主题色，文档站变了，编辑器不会跟着变。

所以第一轮的方案改成：**直接使用 Infima 的菜单类**（`menu__list` / `menu__link` / `menu__caret` / `clean-btn`），让编辑器侧边栏渲染出和文档站相同的 DOM 结构和类名。构建后确认 Infima 的规则全部命中，hover、激活态、暗色模式自动生效。

第一轮结束时的判断是"视觉自动一致了"。这个判断对了一半——后来证明，剩下一半才是真正难的部分。

## 第二轮：多出来的箭头

上线后第一个反馈：分类标题右侧多了一个向下的小箭头。

排查发现是两种箭头的来源被我叠加了。Infima 里分类箭头有两条渲染路径：

- `menu__link--sublist-caret`：箭头通过 `::after` 伪元素挂在链接自己身上；
- `menu__caret` 按钮：一个独立的、只画一个箭头的按钮。

Docusaurus 源码（`DocSidebarItem/Category`）里的规则是：**分类有链接时才渲染独立的 `menu__caret` 按钮**，无链接分类只靠 `--sublist-caret` 的伪元素。我一开始两个都渲染了，于是出现了两个箭头。

第一反应是把 `menu__caret` 按钮删掉、只留伪元素。这修掉了"多一个"，但埋下了第三轮的问题。

## 第三轮：收起按钮与不翻转的箭头

新一轮反馈有三条：文档站收起侧边栏是底部一条干净的 icon 按钮；分类箭头统一靠右，不紧贴标题；收起分类时箭头会翻转，编辑器没有动画。

这三条其实是同一个认知错误的三个症状。重读 Infima 源码后发现：

1. `--sublist-caret` 的 `::after` **没有**折叠时的旋转规则——Infima 的旋转规则只写在 `.menu__list-item--collapsed .menu__link--sublist:after` 和 `.menu__caret:before` 上。也就是说无链接分类的伪元素箭头天生不翻转；
2. 文档站里看到的"靠右 + 翻转"的效果，来自**带链接分类**的渲染路径：`menu__link--sublist`（自身无箭头）+ 独立的 `menu__caret` 按钮。链接 `flex: 1` 把箭头推到行最右，`::before` 的 `transition: transform` 提供翻转动画。

所以正确的复刻不是删按钮，而是换路径：链接改成 `--sublist`，把 `menu__caret` 按钮加回来。第二轮的"修复"方向反了。

同轮还照抄了文档站的收起/展开机制：收起按钮是底部 40px 通栏、居中一个旋转 180° 的 `IconArrow` 双箭头 SVG（就是页面上那个 `fill="#7a7a7a"` 的图标）；侧栏收起时宽度不是归零，而是收成 `--doc-sidebar-hidden-width: 30px` 的竖条，竖条上铺一个展开按钮，hover 是 10% 黑（暗色 10% 白）的叠加。菜单内边距也对齐了文档站 `.menu` 的 `0.5rem` + `scrollbar-gutter: stable`。

## 第四轮：动画被 Infima 自己掐掉了

折叠动画是单独实现的：Docusaurus 用 `Collapsible` 组件做高度过渡，编辑器里用 `grid-template-rows: 1fr → 0fr` 复刻。但上线后发现动画没生效——原因很典型：Infima 有一条 `.menu__list-item--collapsed .menu__list { height: 0 }`，折叠瞬间内容直接消失，过渡自然看不出来。在侧边栏范围内把这条规则还原成 `height: auto`，交给 grid 控制，动画才真正跑起来。

## 为什么花了四轮

回头看，这个任务的难点不在写 CSS，而在三件别的事上。

**第一，信息的分布。** "文档站侧边栏"不是一个东西，是三层：Infima 的基础菜单样式、theme-classic 组件的渲染逻辑（什么时候渲染 caret 按钮、激活态怎么算）、运行时的状态管理（Collapsible、autoCollapse）。第一轮只复用了第一层，类名能保证"涂装"一致，但行为——箭头何时出现、何时旋转、收起后剩多宽——都住在第二、三层里，必须去读组件源码。

**第二，我看不见页面。** 整个过程中唯一能看到渲染结果的是用户。我这边只能从代码推断"应该一致了"，而渲染层面的坑恰恰是代码里看不出来的：两个来源各画一个箭头、一条旋转规则只覆盖两个选择器、一条 `height: 0` 把动画掐死——这些在源码里都是合法且合理的 CSS，只有渲染出来才是 bug。于是每轮返工的本质是：用户当我的眼睛，把视觉差异翻译成文字，我再反推回代码。

**第三，我太快宣布完成了。** 第一轮结束时我说"视觉效果、暗色模式就都自动一致了"，这话只对了静态部分。更诚实的说法应该是：类名复用解决了 80%，剩下 20% 是行为语义，需要读 theme-classic 的源码逐项核对——而我在没有核对的情况下给出了"一致"的结论。第二轮的方向性错误（删 caret 按钮）也是这个心态的产物：用最小改动修掉症状，而不是先搞清文档站为什么那样渲染。

所以如果总结成一条经验：**复刻一个组件，"长得像"和"是同一个"之间隔着一层组件逻辑，这层逻辑不在 CSS 里，在渲染条件的源码里。** 下次遇到类似任务，正确的顺序应该是先把参照物的源码读穿，再动手写第一行样式——而不是先写个大概，再靠视觉反馈一轮轮收敛。

好在收敛的终点是好的：现在编辑器侧边栏和文档站共用同一套 Infima 变量，以后改主题色、切暗色模式，两边永远同步。
